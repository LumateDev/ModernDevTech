# Лабораторная работа №3 — Имитация репликации

## Стек

- ASP.NET Core 9
- In-Memory хранилище (ConcurrentDictionary)
- Docker / Docker Compose
- xUnit (тесты)

## Архитектура

3 узла — одно приложение с разной конфигурацией:

- **Master (A)** — порт 8081, принимает запись и чтение, реплицирует на B и C
- **Replica B** — порт 8082, только чтение
- **Replica C** — порт 8083, только чтение

Данные хранятся в памяти (ConcurrentDictionary). Репликация — синхронная push-модель через HTTP.

## Детали реализации

### Хранение данных

Каждый узел использует собственное in-memory хранилище (`InMemoryStore`), реализованное как `ConcurrentDictionary<string, DataEntry>`. Каждая запись содержит:

- `Key` – строковый ключ
- `Value` – строковое значение
- `Version` – монотонно возрастающий номер (генерируется мастером)
- `Timestamp` – время создания
- `Origin` – идентификатор узла, создавшего запись

При применении реплицированных данных реплика проверяет версию: если версия полученного сообщения больше текущей, запись обновляется. Это обеспечивает **«последняя версия побеждает»** и сохраняет согласованность.

### Репликация

- **Push-модель**. Мастер после успешной локальной записи отправляет `POST /api/replication/apply` на каждую реплику (URL-адреса задаются переменной окружения `ReplicaUrls`).
- Запросы отправляются параллельно через `HttpClient` с таймаутом 5 секунд.
- Ответы от реплик собираются, и клиенту возвращается отчёт: сколько реплик успешно применили изменение.
- Если реплика недоступна (выключена или недоступна по сети), мастер продолжает работу – запись не блокируется.
- Для восстановления данных на реплике после длительного отключения предусмотрен эндпоинт синхронизации: `POST /api/replication/sync-from-master?masterUrl=...`. Реплика получает полный дамп от мастера и применяет все записи с проверкой версий.

### Имитация сбоев

Для тестирования отказоустойчивости реализован сервис `NodeHealthService`. Он позволяет:

- **Выключить узел** (все запросы возвращают 503 Service Unavailable)
- **Включить узел** обратно
- **Установить искусственную задержку** (имитация сетевого лага)

## Запуск

Все сервисы (узлы и тесты) запускаются в контейнерах Docker с помощью Docker Compose.

```bash
docker-compose up --build -d
```

После запуска:

- Мастер: http://localhost:8081
- Реплика B: http://localhost:8082
- Реплика C: http://localhost:8083

Чтобы просмотреть логи работающих узлов:

```bash
docker-compose logs -f master
docker-compose logs -f replica-b
docker-compose logs -f replica-c
```

Остановить все контейнеры:

```bash
docker-compose down
```

## Тестирование

Тесты (xUnit) также запускаются внутри контейнера и проверяют все основные сценарии. Для запуска тестов выполните:

```bash
docker-compose up tests
```

Контейнер с тестами запустится, выполнит все тесты и завершится. Результаты будут выведены в консоль. Пример успешного вывода:

```
Test Run Successful.
Total tests: 8
     Passed: 8
```

## Сценарии тестирования

1. **Базовая репликация** – запись на мастер, чтение с реплик.
2. **Запрет записи на реплику** – возврат 403 Forbidden.
3. **Множественные записи** – все реплицируются.
4. **Падение реплики** – мастер продолжает работу, данные на уцелевшей реплике есть.
5. **Восстановление реплики** – после включения синхронизация с мастером.
6. **Падение мастера** – реплики продолжают обслуживать чтение.
7. **Сетевая задержка** – eventual consistency (данные в итоге согласованы).
8. **Перезапись данных** – побеждает последняя версия.

## Примечания

- Репликация синхронная, но не блокирует ответ клиенту при недоступности реплик – отчёт содержит информацию об успешности.
- Версионирование данных позволяет избежать конфликтов при перезаписи.
- Все узлы используют один и тот же образ, конфигурация задаётся через переменные окружения в `docker-compose.yml`.
- Тесты запускаются в отдельном контейнере, который имеет доступ к узлам по их внутренним именам (`master`, `replica-b`, `replica-c`).
- Для имитации сбоев используются административные эндпоинты, позволяющие выключать узлы, устанавливать задержки и синхронизировать данные.
